# Agent Conversation Renderer - 專案概覽

## 🎯 專案目標

這是一個創新的 **Hybrid UI/UX 對話介面**，讓 AI Agent 能夠在聊天流中嵌入結構化視覺元件，同時在獨立舞台區渲染完整的應用介面。

### 核心理念
- **左側對話流**：承載 Agent 回傳的結構化元件（markdown、info_card、table、step_process 等），讓重點摘要、警示、步驟說明直接出現在聊天氣泡內
- **右側展示舞台**：當 Agent 產出 HTML/SVG/JSON 等完整應用介面時，在更大的畫布上預覽、編輯、比對版本

4. **雙欄介面**

## 🎨 AG-UI Protocol - 元件類型定義

### 基礎元件
1. **markdown** - 一般說明、解釋、段落文字
   ```json
   {"type":"markdown","content":"Markdown 格式文字"}
   ```

2. **info_card** - 重要提示、警告、狀態通知
   ```json
   {"type":"info_card","title":"標題","description":"說明","variant":"info|warning|success|danger"}
   ```

3. **data_list** - key-value 對、屬性清單
   ```json
   {"type":"data_list","title":"標題","items":[{"label":"欄位","value":"內容"}]}
   ```

### 流程與數據元件
4. **step_process** - 操作步驟、流程說明
   ```json
   {"type":"step_process","title":"流程標題","steps":[{"title":"步驟1","description":"說明"}]}
   ```

5. **table** - 比較資料、結構化清單
   ```json
   {"type":"table","title":"標題","headers":["欄1","欄2"],"rows":[["A","B"]]}
   ```

6. **stat_grid** - KPI、數據摘要、指標展示
   ```json
   {"type":"stat_grid","title":"統計標題","items":[{"label":"指標","value":"數值"}]}
   ```

### 程式碼與互動元件
7. **code_block** - 程式碼、指令、設定檔
   ```json
   {"type":"code_block","title":"標題","language":"python","content":"程式碼"}
   ```

8. **action_group** - 建議操作、快速動作清單
   ```json
   {"type":"action_group","title":"動作標題","items":[{"label":"動作","action":"action_id"}]}
   ```

### 完整介面元件
9. **surface** - 完整 HTML 應用介面、SVG 圖表（在右側舞台顯示）
   ```json
   {"type":"surface","kind":"html","html":"<html>...","css":"body{}","title":"標題"}
   ```

## 🔄 三階段生成流程（核心創新）

### 為什麼需要三階段？

傳統單次 LLM 調用容易產生：
- ❌ 全部內容塞進單一 `markdown`
- ❌ 錯誤選擇元件類型
- ❌ JSON 格式不完整或無效

### 解決方案：分工協作

```
Stage 1: 生成內容層
├─ 輸入：使用者問題 + 附件
├─ 輸出：純文本回答 + 建議問題
└─ 職責：確保內容品質與完整性

Stage 2: 元件規劃層
├─ 輸入：Stage 1 的文本內容
├─ 輸出：component 類型清單 + 使用說明
└─ 職責：根據內容特性選擇最適合的視覺化元件

Stage 3: 結構化構建層
├─ 輸入：文本內容 + 元件計劃
├─ 輸出：完整的 AGUIResponse JSON
└─ 職責：將內容轉換為結構化元件 JSON
```

### 範例執行流程

**使用者問題**：「比較 React、Vue 和 Angular 的優缺點」

**Stage 1 輸出**：
```json
{
  "answer": "React、Vue、Angular 是三大主流前端框架...",
  "suggestions": ["如何選擇適合的框架？", "各框架的學習曲線如何？"]
}
```

**Stage 2 輸出**：
```json
{
  "components_to_use": ["info_card", "table", "markdown"],
  "component_descriptions": {
    "info_card": "總結各框架的核心特色",
    "table": "並列比較三者的特性差異",
    "markdown": "補充說明與建議"
  }
}
```

**Stage 3 輸出**：
```json
{
  "components": [
    {
      "type": "info_card",
      "title": "三大框架定位",
      "description": "React 著重靈活性、Vue 強調易用性、Angular 提供完整解決方案",
      "variant": "info"
    },
    {
      "type": "table",
      "title": "特性比較",
      "headers": ["框架", "學習曲線", "生態系", "適用場景"],
      "rows": [
        ["React", "中等", "最豐富", "大型應用、複雜互動"],
        ["Vue", "較低", "成熟", "快速開發、中小專案"],
        ["Angular", "較高", "企業級", "大型企業應用"]
      ]
    },
    {
      "type": "markdown",
      "content": "選擇建議：新手優先 Vue，大型專案考慮 React 或 Angular..."
    }
  ],
  "suggestions": ["如何選擇適合的框架？", "各框架的學習曲線如何？"]
}
```

## 💡 關鍵實作細節

### 1. Artifact 自動偵測與持久化

程式碼中的 `detect_artifact_kind()` 和 `persist_component_artifacts()` 負責：
- 從 `code_block` 和 `markdown` 元件中偵測 HTML/SVG/JSON
- 自動儲存為檔案並加入「模型產出」清單
- 去重機制：相同內容的 artifact 不會重複建立

### 2. 檔案處理支援

```python
# 支援的檔案類型
- PDF：使用 pdfplumber 提取文字
- DOCX：使用 python-docx 提取段落
- 圖片：透過 OpenAI Vision API 分析
- 文字檔：直接讀取（HTML、MD、SVG、JSON、TXT）
```

### 3. 折疊/展開機制

```python
# Session state 追蹤介面狀態
chat_expanded: bool      # 對話欄展開狀態
stage_expanded: bool     # 展示欄展開狀態
split_ratio: int         # 兩欄占比（10-90）
```

### 4. 編輯與版本比對

- **編輯器**：使用 `streamlit_ace` 提供語法高亮
- **Diff 比對**：使用 Python `difflib.HtmlDiff` 產生 HTML diff 視圖
- **版本追蹤**：每個檔案記錄 `original_content`，可隨時比對

### 5. Surface 元件自動展開舞台

```python
# 當 Agent 回傳包含 surface component 時
if has_surface and not st.session_state.stage_expanded:
    st.session_state.stage_expanded = True
    st.session_state.split_ratio = 25  # 自動調整為對話欄 25%
```

## 🚀 開發指引

### 新增元件類型

1. 在 `AGUI_SYSTEM` prompt 中定義新元件格式
2. 在 `render_agui_components()` 中加入渲染邏輯
3. 更新 Stage 2 的 `component_types` 清單

### 新增檔案類型支援

1. 在 `file_icon()` 加入新 icon
2. 實作對應的提取函數（如 `pdf_extract_text()`）
3. 在 `call_openai_stage1_text_content()` 加入處理邏輯

### 客製化 UI 風格

主要 CSS 變數定義在 `st.markdown("""<style>...")` 區塊：
- `--bg / --panel / --panel-strong`：背景層次（暖米 → 奶白）
- `--accent / --accent-soft`：主色調青綠 `#0f766e` 及其淡版
- `--ink / --muted`：文字深淺層次
- `--line`：邊框與分隔線（暖棕 `#d8cdbd`）
- `--user-msg`：使用者氣泡背景（深灰 `#1f2937`）
- `.msg-user`：使用者訊息氣泡
- `.msg-agent`：Agent 訊息氣泡
- `.panel-hdr`：Panel 標題列（`#0f766e → #115e59` 漸層背景）
- `.thinking-bubble`：思考中動畫

## 🎨 設計哲學

1. **漸進式資訊揭露**：先在聊天流看摘要，需要時才展開右側舞台
2. **多模態輸出**：文字、表格、圖表、完整應用介面共存
3. **版本可追蹤**：所有 Agent 產出都可編輯、比對、下載
4. **視覺化優先**：避免純文字堆疊，盡可能用結構化元件呈現

## 🐛 已知限制與改進方向

### 當前限制
- Surface 元件僅支援 HTML/SVG，尚未支援 iframe 或 React
- 三階段生成增加延遲（約 3 倍 API 呼叫時間）
- 檔案上傳後每次 rerun 都會重新讀取（可優化為 cache）

### 未來改進
- [ ] 加入 streaming 支援，讓三階段逐步顯示
- [ ] 支援 Agent 主動觸發工具（如搜尋、計算、API 呼叫）
- [ ] Surface 元件支援 React/Vue 即時預覽
- [ ] 對話歷史持久化（目前僅存在 session state）
- [ ] 多使用者協作模式
